# 延迟推送与会员记账

- 每条合并消息随机延迟30—60秒；允许在区间内设置最小、最大值。相邻消息避开相同延迟秒数。
- 延迟从本条合并消息最新一笔订单进入缓存时开始计算。合并编号、计划发送时间持久保存，重启和重试不重新抽取。
- 同会员、同平台、同期订单合并；计划发送时间、实际发送时间、接收成功时间分别展示。缓存不视为发送成功。
- 到发送时若已知该期结果，或该期预计开奖时间已到，则标记过期，不补发旧单。网络重试沿用同一event_id，接收端须按该编号去重。
- 跟单记账以接收端HTTP成功接收为依据，不等同于外部平台真实成交回执；当前协议没有提供外部平台成交查询。
- 每笔成功推送的策略跟单转换为一笔会员订单。合并消息含两笔跟单，就生成两笔订单、计两笔跟单数。
- 金额来自实际发送的会员金额快照，赔率在生成推送时冻结，不使用模拟策略账户的金额或盈亏。
- 测试、失败、取消、未发送的消息不产生会员订单。显示删除推送记录不删除会员订单、流水或去重记录。
- 成功接收时扣除记账金额；对应期开奖已确认且无未解决冲突后结算，盈利、亏损、退本金独立记录。发送时间不早于实际开奖的历史记录作废并退回记账金额。
- 初次升级时，有非测试推送历史的现有会员初始金额设为1000U，仅执行一次。只有成功接收的历史消息导入订单。未知的历史实际发送时间保持空白，不伪造。
- 后续添加或注册的会员初始金额为0。会员额度为独立记账，不改变或阻止已有推送订阅。
- 增减额度同时改变本金与可用余额，不改变累计订单盈亏。减少不能使本金或可用余额为负。调整使用唯一请求编号防止重复入账。
- 收益率＝已结算会员订单总盈亏÷当前本金；本金为0时显示“—”。跟单数包括待开奖与已结算订单，排除作废订单。
- 完整流水保留操作人、时间、原因、金额、调整前后本金和余额；订单记录关联扣款前、扣款后和结算后余额。
- 订单与资金记录仅管理员可读写。订单支持北京时间起止、期号、会员名、大小单双、状态筛选和10/20/50/100条分页。
