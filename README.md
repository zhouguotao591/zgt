# PC28 本地采集与模拟研究平台

源码和数据目录：`D:\pc28`。Python 3.11+，核心运行只使用标准库。默认只在本机127.0.0.1:8028提供服务。

这是本地模拟平台：没有真实投注平台登录、充值、真实下注或资金转移接口。

## 快速启动

双击 `启动系统.cmd`，保持窗口运行，然后浏览器访问：

http://127.0.0.1:8028

PowerShell也可以运行：

```powershell
cd D:\pc28
.\run.ps1 serve
```

后台运行：右键PowerShell执行 `后台启动.ps1`。停止服务运行 `停止系统.ps1`。后台日志保存在`data/logs`。`设置登录自启动.ps1`为可选脚本，手动运行后注册当前用户登录启动；本次交付没有安装系统计划任务。

启动器优先使用PC28_PYTHON环境变量、项目.venv、当前电脑Codex的Python运行时，再尝试已安装的Python。其他电脑可以安装Python3.11+并设置PC28_PYTHON。源码方式运行无需pip安装。若Windows缺少IANA时区库，执行`python -m pip install tzdata`。

## 功能

1. 开奖采集：定时JSON轮询、官方当年ZIP下载、CSV/ZIP本机导入、重试退避、原始响应归档、缺期检查、每日历史文件复核。
2. 换算：删除NUMBER DRAWN1和20，A取2/5/8/11/14/17，B取3/6/9/12/15/18，C取4/7/10/13/16/19；各组求和取个位。和值≥14为大，≤13为小，奇数为单、偶数为双。CSV保持原列序。
3. 数据质量：20个不重复的1—80整数、期号唯一、全批次导入事务、冲突隔离与人工核对、替换审计、导出全部换算CSV。
4. 本地模拟：下一期决策、每期一个共享账户订单、原子扣款与结算、重启恢复、重复执行去重、参数快照、赔率快照、暂停和风控。
5. 研究：四方向数量差策略、连期反转策略、参数网格、训练/验证分离、固定金额对照、胜率区间、逐单回放与导出。
6. 切换：固定参数/月度第一候选/场景匹配候选三种模式，月界完成旧轮后切换，切换冷却，候选为空则跳过。
7. 运维：本地中文管理页面、CLI、任务队列、持久化运行日志、手动数据库备份和可选登录启动脚本。

## 数据采集配置

在“采集与设置”修改，或停服后修改config.json。

- `collector.latest_url`：默认`https://www.playnow.com/services2/keno/draw/latest/100`，为待现场验证的PlayNow服务适配地址，不是承诺稳定的公开API。
- `collector.archive_url`：官方页面提供的当年ZIP地址`https://www.playnow.com/resources/documents/downloadable-numbers/KenoCurrentYear.zip`。
- `collector.interval_seconds`：默认30秒，最短15秒；每轮优先官方，失败立即尝试备用，下一轮重新优先官方，不因官方失败扩大采集周期。每次重复抓近期记录，以期号幂等入库。
- `collector.proxy`：可选HTTP/HTTPS代理，如`http://127.0.0.1:7890`。没有实现SOCKS协议。程序使用正常TLS验证，不绕过访问限制。
- `collector.source_timezone`：仅在已经确认源时间含义后填写，例如America/Vancouver。ISO时间本身带UTC偏移时无需填写。夏令时依赖时区库；秋季重复小时无法仅凭无时区CSV唯一确定，须人工核验。
- `collector.field_map`：JSON字段映射；支持嵌套点路径，如records=`data.draws`、id=`drawNumber`、time=`drawDate`、numbers=`numbers`。接口字段变化可在高级配置调整。
- `collector.number_order`：最新JSON默认require_ascending，遇到乱序拒绝导入，防止换算口径错误。确认接口与CSV排序关系后才可配置ascending或preserve。CSV始终按原列序。

JSON接受记录数组、单记录对象和常见draws/results/data包装。号码支持整数数组、数字字符串数组、number/value对象数组或逗号分隔字符串。返回HTML拦截页、空数据或不合法号码均报错，绝不制造开奖。

缺期会触发当年官方ZIP补采。最新接口覆盖不足、跨年缺口或官方ZIP尚未更新时，缺口仍显示，不会假装补齐；请从官方页面下载对应年份文件后导入。已经接入用户指定的pc28.world备用源；该latest接口仅返回最新一期，不能据此补齐之前已缺失的历史期次。

官方入口：https://www.playnow.com/keno/winning-numbers/

## 模拟规则

- 此前30期，不含目标开奖；大多买小、小多买大、单多买双、双多买单。
- 默认基础100、亏后2倍、连亏3单结束当前轮，金额路径100→200→400，三连亏损失700。
- 命中后恢复基础金额并继续该轮；每轮总次数上限独立计算。
- 轮结束后下一期重新检查条件；不要求差值先回落再越过门槛。
- 固定方向和参数在轮内不变化，下一轮才切换。错过中间期次后结束旧轮，不把补采的历史结果伪装成当时下注。
- 连亏3单是轮级限制，不是全账户最多只能亏700。账户另有余额、单笔、单日和最大回撤限制。检查下一笔全亏后是否会突破限额。
- 普通命中返还2倍含本金；13/14大小1.99倍、单双1.98倍，沿用原研究假设，必须按真实研究口径确认。整数分、四舍五入结算，不含其他费用。
- 每期最多一单，冲突信号按事先评分顺序选择；不是四个账户收益相加。
- 资金不足或超过限额就跳过，待补开奖的订单先等待结算，账户暂停仍允许既有订单结算。
- 实时数据必须时区明确、最近窗口连续且无未处理冲突；默认结果年龄≤120秒且首次收到后≤60秒才允许决策。超过时窗不补造订单。数据面板的“有效”600秒阈值仅用于数据健康，交易决策更严格。
- 每个目标期号的首次决策固定，跳过后不会因为后来知道更多信息而改写。
- 日级实时报表与亏损限额按UTC日期。源文件无时区时，历史回测日界按源日期，需先确认时区才能与实时逐日严格对照。

## 月度轮换与场景切换

默认搜索220组：四方向×（8个数量差门槛×5个轮上限 + 3个反转连期长度×5个轮上限）。可在高级配置改网格。基础100/倍数2/连亏3保持固定。

例：11月使用候选，7—9月训练，10月验证，11月本地模拟。训练先按净收益/回撤分数选出每方向最多3组，然后验证样本数量、净收益、投入收益率、回撤和固定100下注对照收益。默认验证至少300笔，训练至少1000笔，验证收益和固定金额对照都要大于0，回撤≤15000。还检查起止日覆盖、已观察到进入下个月的边界记录与期号连续；这不能证明上游未漏报尚不存在于数据库的最新期次。

- fixed：使用配置的固定参数，不经月度候选准入，适合对照模拟。
- monthly：只使用该月评分第一的合格候选；没触发则跳过。
- adaptive：按评分优先级，选择当前场景触发的合格候选；轮内不切换。

月度候选在首次完整评估发布后冻结；同月重复研究可导出结果，但不会重写已启用名单。验证数据不完整时不发布名单，每6小时重试。发现历史修正会使旧候选失效并暂停账户，需要人工核对。月度筛选只读取月初前的数据，不能据未来月份来调当月策略。实时自动筛选月份按UTC月界触发，历史分段按源日历月份；边界附近需结合已确认的源时区解释。

滚动验证会逐月生成候选，再把后续月份放进一个共享账户回放，执行组合风控、冷却和每期一单；用于评估“选策略的方法”。报告包括被筛掉/没有候选的月份。

历史筛选、胜率置信区间和固定金额对照仍无法消除多重搜索偏差；置信区间为普通逐单Wilson区间，未作时序依赖/多重比较校正，不应作为已证实优势。建议保留之后新增数据做未参与调参的前向模拟。找不到合格候选是正常结果。

## 历史缺期比对与补齐

“开奖数据库 → 数据质量 → 比对并补齐历史缺期”会从pc28.world历史接口按before游标分页取数，先备份数据库，校验20个号码和ABC，再补入本地缺失期数。同一期已存在时比较原始号码与换算结果；冲突隔离，不静默覆盖。源只返回衍生结果、原始Keno为null的缺失期会保留待补，不伪造原始号码。

命令：`.\run.ps1 sync`。默认最多20页，每页200期；范围从已有本地最早期号到首次请求时上游最新期号，不扩展到1995年以来的全部历史。每次结果和备份位于data/exports/history-sync-*.json及before-history-sync-*.sqlite3。该操作可手动重复执行，已有数据去重。


固定参数回测现可单独填写亏损后递增倍数（1—5倍、两位小数）和连续亏损停轮期数（1—10期），默认2倍/3期。回测结果显示实际使用参数，逐单CSV按这些参数计算。CLI示例：`.\run.ps1 backtest --loss-multiplier 1.5 --max-losses 2 --unlimited`。该表单仅控制本次历史回测，不修改运行中的模拟策略。

## 历史回测页面

## 每日暂停休息与末期保护

按PlayNow每天太平洋时间04:00—04:30暂停处理，期间首页、全局状态和浮窗统一显示“暂停休息中”。BC在2026-03-08起保持UTC-7，当前对应北京时间19:00—19:30；暂停日历独立于旧CSV/source_timezone转换，不重写历史开奖。来源：https://www.playnow.com/about-playnow/help.html 与 https://news.gov.bc.ca/releases/2026AG0013-000209 。

所有策略禁止暂停前最后一期（通常暂停开始前3分30秒）新开单，暂停期间及仍只有暂停前末期数据时也不新开单。已有订单继续按真实结果结算，收到恢复后的新结果后重新判断。反转策略结束旧轮后重判；小时跟随不在休息期间新建跟随段。正常维护造成的连续期号时间间隔不当作缺期，小时覆盖检查相应识别已知暂停。

倒计时同时识别近期至少3天重复的连续期号发布间隔，估计首期恢复时间并明确标注“历史推算”，到点自动拉取，超时显示延迟而非无限等待。返回旧期的备用接口会标记stale/resting，不再一律记作成功；不会据倒计时或历史规律伪造开奖结果。正式采集仍每30秒执行。

后台“AI概率研究”可查看训练进度并重新训练。后台自动每周更新模型；运行中的统计和推送相互独立。模型由历史基准、平滑条件统计和正则化逻辑回归组成；默认90天训练、14天校准，后7天测试，向前滚动最近6个完整测试段。特征只使用目标期之前的开奖；模型选择和校准不读取测试段结果。每个预测期号与维度只能留档一次，重新训练不会覆盖旧预测。

AI训练需服务所用Python环境安装NumPy：`python -m pip install -r requirements-ai.txt`。未安装时仅AI训练提示依赖问题，现有功能继续运行。正式站点首次模型已完成本地训练；可在后台重新运行。模型、逐期样本外结果与线上预测分别存入ai_models、ai_validation、ai_predictions。

“历史验证支持”要求足够的验证样本，并相较50%及训练期占比基准表现出稳定的概率误差改善；其他情况标记“未验证优势”。历史回放假设结果及时可用，线上评价排除开奖后才生成的记录。AI分析不创建模拟或实际订单，不向机器人发送消息。

AI独立模拟（2026-11-05）：前端常用工具 → AI分析，大小/单双分开留档，判断为校准模型概率超过50%的一方，正好持平时不模拟。使用独立 ai_paper_orders 表保存开奖前的方向、金额和赔率快照，不修改策略账户、会员配置或机器人队列。未中金额500→600→750→500循环，命中（含退本金）恢复500，重启后沿用记录计算下一笔。数据过期或官方休息期不生成新单；不补造缺失的线上判断。展示20/50/100期不改变线上金额。样本外历史回放来自ai_validation，每个窗口从500起、按当前赔率重算，与上线后的模拟记录分别展示。

多推送平台：后台「机器人推送 → 推送平台管理」新增、编辑和启停平台，每个平台使用独立HTTP/HTTPS接口与DPAPI加密密钥。原有地址、密钥和会员绑定自动归入默认本机工具。会员绑定新增平台选择，同一会员可在不同平台分别订阅并配置固定金额或模拟金额比例。同平台内会员、账号/机器人组合唯一；各绑定的同期订单独立合并、去重和重试。修改平台会取消尚未发送的旧消息；平台停用后不采集该平台的新消息；没有历史补发。远程地址必须能从PC28服务器连通，接收端仍须按event_id去重，消息协议为现有 /api/v1/signals Bearer认证。

历史回测期数口径（2026-11-05）：结果分别展示开奖总期数、实际下单/结算数、未下单期数和时间校正数，并直接列出主要跳过原因。最大回撤限制属于整个回测账户，不自动按日重置，保持现有策略风控。source_window 对已确认的官方历史CSV重复小时，仅在前后期号连续、210秒间隔完全吻合且时间偏差恰好1小时的情况下做回放内修正；coverage.time_repairs保存原时间、校正时间和依据，原始数据库时间、实时订单、账户不修改。无法核验的逆序数据继续排除。

上期跟随金额计数（cumulative-v2）：加额、减额分别累计已结算亏损/盈利次数，输赢交替或退本金不清零；任一累计项达到配置上限后，下一单使用基础金额，并同时清零两项计数。0代表该项不限。配置调额值为0时该项不计数；已触及金额下限时盈利仍计减额次数。旧版运行状态首次执行新规则时重新开始累计，不追改历史订单；新回测从窗口起点按新规则完整重放，结果标注amount_counting=cumulative-v2。

自定义范围（2026-11-05）：图形走势支持勾选大、小、单、双独立单曲线，统计上限20000期；珠路仅显示最近200期，折线使用所选全部数据。历史回测支持默认三个月、北京自定义起止时间或最近20—100000期，最早2024-01-01。时间范围超过100000期或有效数据不足20期时明确拒绝，不静默截断。自定义结果独立保存，不覆盖策略列表固定近1/3个月收益缓存。回测数据截止、策略参数、赔率在提交时冻结，继续执行原风控和窗口内预热。

历史回测收益K线：结果接口支持interval=1h/4h/1d。基于history_backtest_orders全部已结算订单的pnl（分）顺序累计并按北京时间整点/0、4、8…点/午夜分桶，开盘为时段前累计收益，高低包括开盘与每笔结算后收益，收盘为时段最后累计收益；空时段平盘延续。既有回测无需重跑，聚合结果按run_id/周期缓存最多24组。界面红涨绿跌，横向滚动，右侧收益轴固定，悬停显示开高低收及订单数。
